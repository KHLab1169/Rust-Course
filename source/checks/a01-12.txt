- `error: unrecognized subcommand 'lsit'`
- `todo 0.3.0`
WHY: clap suggests close matches for typos. The first line names the problem; the tip line offers the likely intended subcommand.

=== A11.2/3
Q: Where does clap's help text for each option come from?
+ The doc comments on the struct's fields.
- A separate `help.txt` file.
- The field names only.
- Comments starting with `//`.
WHY: `///` comments become help lines, so documentation and parsing come from one struct and can't drift apart.

=== A11.3/2 pick
Q: The client requests `/authors`, which the server doesn't have. What does the first line about it say?
+ `404 is still Ok(response): status 404 Not Found`
- `404 is still Ok(response): status 200 OK`
- `after error_for_status: error with status Some(404)`
WHY: reqwest treats any HTTP status as a successful request. Only `error_for_status()` turns 4xx and 5xx into errors.

=== A11.3/3
Q: Which failure is worth retrying?
+ A 503 Service Unavailable response.
- A 404 Not Found response.
- A 400 Bad Request response.
- A 401 Unauthorized response.
WHY: 503 (like 429, timeouts and refused connections) is often temporary. Client errors such as 404 will fail the same way on every retry.

=== A12.1/2 hide
Q: A request body `{"txt":"typo"}` is sent to `POST /notes`, whose handler expects `{"text": ...}`. What comes back?
+ A 422 response from the `Json` extractor saying the field `text` is missing; the handler never runs.
- A 201 response with an empty note.
- A 500 response because the handler panicked.
- A 422 response from the handler saying "text must not be empty".
WHY: Extractors validate the request before the handler is called, so a body of the wrong shape is rejected automatically. The handler's own empty-text check only sees well-formed bodies.

=== A12.1/3
Q: Why do internal errors return a generic "something went wrong" message?
+ To avoid leaking details like database errors to clients, while logging them in full on the server.
- Because 500 responses can't have a body.
- Because axum truncates messages.
- To make responses faster.
WHY: Clients get a consistent JSON error; operators get the details in the logs. Leaking internals helps attackers and confuses users.

=== A12.2/2 predict
Q: Three bugs are inserted with severities 1, 4 and 2. The query selects `severity <= 2 ORDER BY severity`. Which bug is printed second?
+ `Bug { id: 3, title: "Slow search", severity: 2, assignee: Some("bo") }`
- `Bug { id: 2, title: "Typo in menu", severity: 4, assignee: None }`
- `Bug { id: 1, title: "Slow search", severity: 2, assignee: Some("bo") }`
WHY: Only severities 1 and 2 pass the filter, sorted ascending, so "Slow search" (id 3) comes after "Crash on save".

=== A12.2/3
Q: Why did the query built with `format!` match every user?
+ The input's `' OR '1'='1` became part of the SQL and changed the query's logic.
- `format!` lowercases the input.
- SQLite ignores the WHERE clause in formatted queries.
- The parameterised query had a bug.
WHY: That's SQL injection. Parameters send the input as a value only, so it can never change the query's structure.

=== A12.3/2
Q: Why does `c_len` create a `CString` before calling `strlen`?
+ C needs a NUL-terminated string, and `CString` guarantees one (rejecting text with an inner NUL).
- `strlen` only accepts heap memory.
- Rust strings can't be passed by pointer.
- To convert the text to ASCII.
WHY: Rust `&str` isn't NUL-terminated. `CString::new` adds the terminator and fails if the text already contains a NUL byte, which C would treat as the end.

=== A12.3/3
Q: What is required to call a function declared in an `unsafe extern "C"` block?
+ An `unsafe { }` block at the call site, ideally with a SAFETY comment.
- Nothing: foreign functions are safe by default.
- Building with `--release`.
- Marking `main` as `extern "C"`.
WHY: The compiler can't check what C code does with the arguments, so the caller must promise it's correct. Wrapping the call in a safe function contains that promise.

=== A12.4/2
Q: Why keep the markdown statistics in a plain Rust function rather than behind `#[wasm_bindgen]`?
+ It can be tested natively with `cargo test`, and the wasm layer stays thin.
- wasm-bindgen functions can't contain loops.
- Plain functions run faster in the browser.
- WebAssembly can't use structs.
WHY: The browser-specific code is just a wrapper. All the logic gets fast, ordinary tests.

=== A12.4/3
Q: Which Cargo setting is needed for a crate built with wasm-pack?
+ `crate-type = ["cdylib", "rlib"]` under `[lib]`
- `edition = "wasm"`
- `target = "browser"` under `[package]`
- `panic = "unwind"`
WHY: `cdylib` produces the `.wasm` module; `rlib` keeps the crate usable by native tests and other Rust crates.
