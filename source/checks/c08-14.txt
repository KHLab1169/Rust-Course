=== 8.1/3
Q: When is direct indexing `v[i]` a better choice than `v.get(i)`?
+ When an out-of-range index would mean a bug, so stopping with a panic is the right reaction.
- When the index comes from user input.
- When you want the program to keep running after a bad index.
- Always: `get` is slower and should be avoided.
WHY: `get` is for situations where a missing element is normal and must be handled. Indexing states "this index is always valid", and a panic exposes the bug if it isn't.

=== 8.2/2
Q: Why does Rust refuse `s[0]` on a String but allow `s.chars().nth(0)`?
+ Characters can take several bytes in UTF-8, so a plain number has no single meaning; `chars()` walks real characters.
- Strings are stored backwards in memory.
- Indexing would copy the whole string.
- `chars()` only works on ASCII text.
WHY: "café" is 5 bytes but 4 characters. Rust makes you say whether you want bytes (`as_bytes()`), characters (`chars()`) or a byte range slice.

=== 8.2/3

- `greeting[0]`
- `greeting.first()`
- `greeting.get(0)`
WHY: `chars()` iterates over characters and `next()` returns the first one as an `Option<char>` (None for an empty string). Strings can't be indexed by an integer.
