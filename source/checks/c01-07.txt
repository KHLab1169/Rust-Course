=== 1.1/2
Q: Which command brings your installed Rust toolchain up to the latest stable release?
+ `rustup update`
- `cargo update`
- `rustc --upgrade`
- `cargo install rust`
WHY: rustup manages toolchains, so `rustup update` upgrades rustc, cargo and the docs together. `cargo update` only refreshes a project's dependencies in Cargo.lock.

+ `println!` is a macro, so the compiler checks the format string against the arguments at compile time.
- The operating system checks every string before running a program.
- Cargo runs the program once in the background to look for errors.
- Rust converts the missing argument to an empty string and warns.
WHY: Macros expand at compile time, so the number of `{}` placeholders and arguments is checked during compilation. Many languages only discover this when the line runs.

=== 1.3/2
Q: You only want to know whether your code compiles, as fast as possible. Which command fits best?
+ `cargo check`
- `cargo build --release`
- `cargo run`
- `cargo new`
WHY: `cargo check` type-checks without producing an executable, which is much faster than a full build. A release build is the slowest option, because it optimises.

=== 2.3/3
Q: Why is it useful that the compiler rejects a `match` that forgets `Ordering::Equal`?
+ If a case is ever missed, including a variant added later, the compiler points at every `match` that must handle it.
- It makes the program run faster.
- It stops you from using `match` with numbers.
- It automatically adds a default arm for you.
WHY: Exhaustiveness checking means a `match` can be trusted to handle every case. Adding a variant to an enum later turns every incomplete match into a compile error.

=== 3.2/2
Q: What do `300 as u8` and `u8::try_from(300)` do?
+ `as` silently truncates to 44, while `try_from` returns an error.
- Both panic, because 300 does not fit in a u8.
- Both give 255, the largest u8.
- `as` returns an error and `try_from` truncates to 44.
WHY: `as` keeps only the low 8 bits (300 − 256 = 44) without complaint. `try_from` checks the range and reports `Err` when the value does not fit.

=== 3.2/3
Q: How do you fix multiplying `items: i32` by `price: f64`?
+ Convert explicitly, for example `items as f64 * price` or `f64::from(items) * price`.
- Add `#[allow(mixed_types)]` above the function.
- Nothing: Rust converts the i32 to f64 automatically.
- Declare both as `let` without types.
WHY: Rust never converts between number types implicitly, because every implicit conversion could silently lose precision. You choose the conversion and write it out.

=== 3.3/3
Q: What does Rust do when you index an array past its end, like `months[7]` on a 3-element array?
+ It panics with "index out of bounds" and stops before touching memory it does not own.
- It returns whatever value is stored in memory after the array.
- It returns 0.
- It wraps around and returns `months[1]`.
WHY: Every index is bounds-checked. A clear panic is far better than silently reading garbage, which is what the same mistake can do in C. Use `get` when an index might be out of range.

=== 3.4/3
Q: Why does `fn square(x: i32) -> i32 { x * x; }` fail to compile?
+ The semicolon makes `x * x;` a statement, so the body evaluates to `()`, not an `i32`.
- Functions must always use the `return` keyword.
- `x * x` can overflow, so the compiler rejects it.
- Parameters cannot be used in arithmetic without `mut`.
WHY: A block's value is its final expression. Adding a semicolon turns that expression into a statement, leaving the unit value `()`. Removing the semicolon fixes it.

=== 3.5/3

=== 4.3/3
Q: Why does the compiler refuse `scores.push(...)` while `first` still borrows an element?
+ `push` may reallocate the vector's buffer, which would leave `first` pointing at freed memory.

=== 5.3/2
Q: Why can't `small` be used after `small.into_square()`?
+ `into_square` takes `self` by value, so it consumed `small`.
- `into_square` takes `&mut self` and locks `small`.
- Methods that start with `into` delete their struct.
- `small` was not declared `mut`.
WHY: A method's receiver decides what happens to the value: `&self` borrows, `&mut self` borrows mutably, and `self` takes ownership. By convention, `into_*` methods consume.

=== 7.1/2

+ From the file layout: `src/main.rs` is the default binary and every file in `src/bin/` is another.
- Each binary must be listed in `Cargo.lock`.
- Binaries are detected by searching for `fn main` in every file.

WHY: Cargo follows conventions: `lib.rs` is the library, `main.rs` the default binary, and `src/bin/*.rs` extra binaries. No configuration is needed.

=== 7.1/3

+ Logic that returns values can be tested and reused; `main` only handles input and output.
- Printing is not allowed inside modules.
- Returning data is faster than printing.
- Library crates cannot use `println!`.
WHY: Keeping logic pure and pushing input and output to the edges is the professional shape: tests call `analyse` directly, and other binaries can reuse it.
